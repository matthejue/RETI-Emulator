Assemble mode requires a same-basename `.sections` file next to the `.reti` input. The `.sections` JSON must contain `codesegment_start`, `datasegment_start`, `heap_start`, `heap_size`, and `stack_start`. It may also contain an optional interrupt-service-routine start entry before `codesegment_start` when the `.reti` SRAM image begins with numeric interrupt-vector-table entries:

```json
{
  "interrupt_service_routines_start": 1,
  "codesegment_start": 16,
  "datasegment_start": 4572,
  "heap_start": 4600,
  "heap_size": -1,
  "stack_start": 8000
}
```

`interrupt_service_routines_start` is optional. It is emitted only when the `.reti` SRAM image starts with numeric interrupt-vector-table entries. The value is a SRAM-relative address: the word offset where the interrupt service routines begin after those vector-table entries. When present, the emulator can display memory before that address as vector-table values and memory from that address up to `codesegment_start` as RETI instructions.

If the `.reti` SRAM image does not start with numeric interrupt-vector-table entries, `interrupt_service_routines_start` must be omitted and the layout is:

```json
{
  "codesegment_start": 0,
  "datasegment_start": 4572,
  "heap_start": 4600,
  "heap_size": 1200,
  "stack_start": 8000
}
```

`heap_start` is the SRAM-relative address where the heap can begin, directly after the last allocated global data word.

`heap_size` is the requested number of heap words. `-1` asks the loader to use its default; edit the generated `.sections` file before assembly to request an explicit size.

`-a/--assemble` writes `codesegment_start`, `datasegment_start`, `heap_start`, `heap_size`, and `stack_start` as the first five encoded 32-bit words in the generated `.bin`, before appending the encoded SRAM words from the loaded `.reti` program. `interrupt_service_routines_start` is metadata for debug display and is not written into the binary header.

For normal execution without `-e`, `stack_start` also affects the autogenerated EPROM start program. `stack_start: -1` keeps the old behavior and places `SP` at the end of SRAM; any other value sets `SP` to that offset plus the SRAM address-space constant.
